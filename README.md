# mcp_mtproto

MCP-сервер, який дає Claude доступ до вашого Telegram через протокол MTProto (бібліотека [Telethon](https://github.com/LonamiWebs/Telethon)):
читати історію чатів і каналів, шукати повідомлення, завантажувати фото й файли, дивитися учасників, працювати з ботами.

Сервер працює **локально, на вашому комп'ютері**, і входить у Telegram **під вашим особистим акаунтом** (не через бота — інакше історію чужих груп прочитати неможливо).

**Куди потрапляють дані.** Сам сервер нікуди, крім Telegram, не звертається. Але його призначення — віддавати дані Claude, тож ланцюжок такий: Telegram → локальний сервер → MCP-хост (Claude Desktop / Claude Code) → **модель, яку використовує хост**. Тексти повідомлень, імена учасників, відповіді ботів, які повертає інструмент, хост передає моделі — для Claude це хмара Anthropic, за правилами вашого облікового запису. Локальний транспорт (stdio) цього не змінює. На диску (`data/`) лишаються лише файл сесії, завантажені медіа й вивантаження; вміст файлів потрапляє до моделі тільки тоді, коли Claude їх відкриває.

> ⚠️ Файл сесії `data/session.session` дає **повний доступ до вашого Telegram-акаунта**. Нікому його не передавайте, не комітьте в git, не заливайте в хмару. Якщо файл потрапив до чужих рук — відкрийте Telegram → Налаштування → Пристрої й завершіть цей сеанс.

## Що вміє

| Інструмент | Що робить |
|---|---|
| `list_dialogs` | список ваших чатів, каналів і ботів (id, назва, тип) |
| `join_channel` | вступити в канал чи групу за `@username` або запрошувальним посиланням (`t.me/+…`, `t.me/joinchat/…`) |
| `get_history` | історія повідомлень чату за період |
| `search_messages` | пошук за ключовими словами всередині чату |
| `export_chat_md` | вивантажити історію чату в Markdown-файли, розбиті на частини за розміром (працює у фоні) |
| `export_status` / `export_resume` / `export_cancel` | стан вивантаження, продовження після паузи чи збою, скасування |
| `download_media` | завантажити фото, відео, аудіо й файли з повідомлень у `data/media/<id чату>/` (до 1,5 ГБ на файл) |
| `list_participants` | список учасників (якщо чат його не приховує) |
| `send_to_bot` | надіслати **боту** повідомлення чи команду й дочекатися відповіді (людям і в групи не пише) |
| `get_recent_bot_messages` | останні повідомлення бота (щоб побачити кнопки) |
| `click_button` | натиснути inline-кнопку на повідомленні бота за її текстом |

Усе, крім `join_channel`, `send_to_bot` і `click_button`, нічого не змінює в Telegram. Ці три дії видимі для інших: акаунт справді вступає в канал або пише боту. Вони виконуються тільки тоді, коли ви (або Claude за вашим проханням) явно їх викликаєте. Кожен інструмент має MCP-анотації (`readOnlyHint` тощо), за якими хост може просити підтвердження для дій із побічними ефектами. `download_media` і вивантаження пишуть файли лише на ваш диск.

Помилки, які можна виправити, інструменти повертають однаково: `{"ok": false, "code": "...", "error": "текст"}`. Для обмеження частоти запитів — `code: "flood_wait"` і `retry_after` (секунд).

## Вимоги

- **Python 3.11 або новіший** (перевірити: `python3 --version` на macOS, `py --version` на Windows).
- Telegram-акаунт з номером телефону.
- Claude Desktop або Claude Code.
- macOS або Windows (на Linux працює так само, як на macOS).

## Крок 1. Отримайте `api_id` і `api_hash` у Telegram

Telegram вимагає, щоб кожен, хто підключається до нього не через офіційний додаток, мав власні ключі. Це безкоштовно й займає кілька хвилин.

1. Відкрийте <https://my.telegram.org/apps> у браузері.
2. Введіть номер телефону вашого Telegram-акаунта (у міжнародному форматі, наприклад `+380...`) і натисніть «Next».
3. Telegram надішле **код входу в сам додаток Telegram** (не SMS) — у чат «Telegram». Введіть його на сайті.
4. Натисніть **API development tools**.
5. Якщо застосунку ще немає, заповніть форму «Create new application»:
   - **App title** — будь-яка назва, наприклад `MCP Telegram`;
   - **Short name** — коротка назва латиницею, 5–32 символи, наприклад `mcptg`;
   - **Platform** — `Desktop`;
   - **Description** — необов'язково.
6. Натисніть «Create application». На сторінці з'являться **App api_id** (число) та **App api_hash** (рядок із 32 символів). Збережіть їх — вони знадобляться на кроці 4.

Поради:
- `api_hash` — секрет. Не публікуйте його, не надсилайте в чат і не комітьте.
- Якщо сайт показує помилку («ERROR») при створенні застосунку, спробуйте ще раз пізніше, з іншого браузера, а також без VPN/проксі — це відома примха сайту Telegram.
- Використовуйте той номер, яким будете логінитися в сервері на кроці 5.

## Крок 2. Завантажте код

```
git clone https://github.com/vredin/mcp_mtproto.git
cd mcp_mtproto
```

Не маєте git — натисніть на GitHub «Code → Download ZIP», розпакуйте архів і відкрийте термінал у цій папці.

## Крок 3. Створіть віртуальне середовище й встановіть залежності

### macOS (Terminal)

```
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -c requirements.lock
```

### Windows (PowerShell)

```
py -3 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt -c requirements.lock
```

`requirements.lock` — перевірений набір версій. Якщо якась із них не встановлюється на вашій версії Python, виконайте просто `pip install -r requirements.txt`: там версії обмежені сумісними гілками (зокрема `mcp` 1.x — у 2.x сервер не запуститься).

Якщо PowerShell відповідає, що виконання скриптів вимкнене, або виконайте один раз
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, або скористайтеся командним рядком (cmd) і `.venv\Scripts\activate.bat`. Також можна взагалі не активувати середовище, а викликати Python напряму: `.venv\Scripts\python.exe ...`.

## Крок 5. Один раз увійдіть у Telegram

Це інтерактивний крок, його робить людина в терміналі.

### macOS

```
.venv/bin/python -m app.auth
```

### Windows

```
.venv\Scripts\python.exe -m app.auth
```

Програма запитає:
1. **номер телефону** (у форматі `+380...`);
2. **код** — він прийде в додаток Telegram на іншому вашому пристрої (або SMS, якщо додатка немає);
3. **пароль двоетапної перевірки** (2FA), якщо ви його вмикали.

Після успіху з'явиться повідомлення «Вход выполнен: …» і файл `data/session.session`. Далі сервер входить сам, без запитань. Цей крок повторювати не треба, поки ви не завершите сеанс у Telegram.

Папка `data/` створюється з правами `700`, файл сесії — `600` ще до того, як у нього щось запишеться (macOS/Linux). Якщо права ширші — сервер їх виправить. Вхід не виконається, поки запущено MCP-сервер: сесією одночасно володіє лише один процес.

## Як користуватися

Просто пишіть Claude звичайною мовою. Приклади:

- «Покажи мої чати» → `list_dialogs`.
- «Знайди в чаті про оренду в Софії згадки про "Лозенець" за останній тиждень» → `search_messages`.
- «Завантаж фото з повідомлень 15098 і 15101 у чаті про оренду» → `download_media`.
- «Вивантаж чат про оренду за 2026 рік у md» → `export_chat_md`.

### Як вказувати чат

**Номер повідомлення унікальний лише в межах одного чату**, тому завжди називайте чат. В інструмент можна передати:

- числовий id з `list_dialogs` (наприклад `-1001234567890`) — рядком або числом;
- `@username`;
- посилання `t.me/...`.

Якщо ви називаєте чат словами, Claude сам знайде його id через `list_dialogs` (за замовчуванням повертаються перші 50 чатів, максимум — 1000). Якщо чату з таким id ще немає в локальному кеші сесії, сервер сам завантажить список діалогів і спробує ще раз — це може зайняти кілька секунд при тисячах чатів. Невідомий чат — `code: "not_found"`.

### Історія й пошук

- Період `since`/`until` — це інтервал **[since, until)**: `since` включно, `until` — ні (`until=2026-10-01` означає «до початку 1 жовтня»). Так само працює вивантаження. `since` має бути раніше за `until`.
- Ліміти за один виклик: `get_history` — до 5000 повідомлень, `search_messages` — до 1000, `list_participants` — до 10 000, `get_recent_bot_messages` — до 100.
- Продовження: передайте в `before_id` найменший id з попередньої відповіді — отримаєте давніші повідомлення.

### Завантаження медіа (`download_media`)

- Файли лежать у `data/media/<id чату>/<номер повідомлення>.<розширення>`, поруч — `<номер>.meta.json` (id вкладення в Telegram і розмір). Файли не видаляються автоматично.
- Ліміт — до **1,5 ГБ** на файл (параметр `max_size_mb`, за замовчуванням і максимум — 1536) і до 50 повідомлень за виклик.
- **Кеш перевіряється**: повторний запит бере файл із диска (`cached: true`), лише якщо вкладення в Telegram те саме й розмір файлу збігається. Якщо в повідомленні замінили файл чи фото — завантажиться нове.
- Кожне завантаження пишеться в окремий тимчасовий файл `.<номер>.<випадкове>.part`, після завершення **перевіряється розмір** (для документів — точний збіг із Telegram) і лише тоді файл публікується атомарно. Недокачаний файл не потрапить у кеш; якщо розмір не збігся — повернеться `code: "incomplete_download"`.
- Одночасні запити того самого повідомлення виконуються по черзі: другий отримає вже завантажений файл.
- Великі відео качаються хвилинами, і Claude може обірвати виклик за таймаутом. Тоді зменште кількість файлів за раз або повторіть запит.

### Вивантаження чату в Markdown (`export_chat_md`)

Вивантаження — це **фонове завдання** (`job_id`). `export_chat_md` чекає до `wait_seconds` (за замовчуванням 20, максимум 50): невеликий чат встигне вивантажитися, і ви одразу отримаєте шляхи. Інакше повернеться `status: "running"` — Claude перевіряє стан через `export_status(job_id)`, не впираючись у таймаут.

Готовий результат з'являється в `data/exports/<id чату>/<job_id>/` **тільки повністю**: частини збираються в `data/exports/.jobs/<job_id>/` і в кінці публікуються одним перейменуванням папки разом із `manifest.json` (`"status": "complete"`, параметри, кількість повідомлень, список частин). Немає `manifest.json` — немає готового вивантаження. `job_id` унікальний, тож навіть два запуски в ту саму секунду не перезапишуть один одного.

Файли розбиваються на частини з іменами `001_<перша дата>_<остання дата>.md`. Нова частина починається, коли наступне повідомлення **разом із заголовком частини** вже не вміщується в ліміт:

| Параметр | За замовчуванням | Навіщо |
|---|---|---|
| `max_words` / `--max-words` | 400 000 слів (мінімум 100) | NotebookLM приймає до 500 тис. слів на джерело |
| `max_mb` / `--max-mb` | 10 МБ (до 200) | Perplexity приймає близько 25 МБ на файл, але з великими файлами пошук працює гірше |
| `by_month` / `--by-month` | вимкнено | додатково починати нову частину з кожного місяця |

Повідомлення, яке саме більше за ліміт, не ріжеться: воно йде окремою частиною, а її ім'я є в `oversized_parts` результату й позначено `oversized` у `manifest.json`.

Без `--by-month` маленькі місяці склеюються в один файл — частин менше, і простіше вкластися в ліміт кількості джерел (NotebookLM Free — 50 джерел на блокнот, Perplexity Pro — 50 файлів на проєкт).

Формат повідомлення:

```md
### 2026-09-01 12:34 UTC · Іван Петренко (@ivan) · #15098

> відповідь на #15090
Здається квартира в **Лозенці**…
📎 Photo — скачать: download_media(message_ids=[15098])
```

- Форматування тексту (жирний, посилання) зберігається в Markdown; позначаються відповіді, пересилання й службові повідомлення.
- Медіа не завантажуються: для кожного файлу є рядок 📎 з типом, назвою, MIME і розміром та номером повідомлення для `download_media`.

**Статуси завдання** (`export_status`):

| Статус | Що означає | Що робити |
|---|---|---|
| `running` | виконується у фоні | чекати, перевіряти `export_status` |
| `waiting_flood` | Telegram попросив зачекати (до 15 хв) — сервер чекає сам | нічого |
| `paused` | Telegram попросив чекати довше; `retry_after` — скільки секунд | через цей час — `export_resume(job_id)` |
| `interrupted` | процес, що виконував завдання, завершився (закрили Claude) | `export_resume(job_id)` |
| `cancelled` | скасовано `export_cancel` | за потреби — `export_resume(job_id)` |
| `failed` | помилка, текст у `error` | виправити причину, `export_resume(job_id)` |
| `complete` | готово: `dir`, `files`, `oversized_parts` | — |

`export_resume` продовжує з останньої готової частини за id повідомлення — вже вивантажене не обробляється вдруге. `export_status` без `job_id` показує останні завдання. Стан завдань зберігається в `data/exports/.jobs/` і переживає перезапуск; цю папку можна видалити, коли незавершені завдання не потрібні.

**З терміналу** — коли Claude закритий (сесією володіє один процес, див. «Усунення проблем»). Тут таймауту немає, і FloodWait до доби сервер перечікує сам:

macOS:
```
.venv/bin/python -m app.export <id чату, @username або t.me/...> [--since 2026-01-01] [--until 2026-10-01] [--max-words 400000] [--max-mb 10] [--by-month]
.venv/bin/python -m app.export --list
.venv/bin/python -m app.export --resume <job_id>
```
Windows:
```
.venv\Scripts\python.exe -m app.export <id чату, @username або t.me/...> [--since ...] [--until ...] [--max-words ...] [--max-mb ...] [--by-month]
.venv\Scripts\python.exe -m app.export --list
.venv\Scripts\python.exe -m app.export --resume <job_id>
```

`Ctrl+C` зупиняє вивантаження зі статусом `interrupted` — його можна продовжити через `--resume`.

### Вступ у канали (`join_channel`)

- Приймає `@username`, `t.me/name`, `t.me/+hash`, `t.me/joinchat/hash` або просто `+hash`.
- Повертає id у тому ж форматі, що й `list_dialogs` (`-100…`) — його одразу можна передавати в інші інструменти.
- Якщо ви вже учасник, повертає `already_member: true` і нічого не робить повторно.
- Окремі відповіді: заявку надіслано адміну на схвалення (`pending: true`), посилання недійсне чи прострочене, `@username` належить людині чи боту, а не каналу.

### Робота з ботами (`send_to_bot`, `get_recent_bot_messages`, `click_button`)

- Працюють **лише з ботами**: якщо передати id людини чи групи, інструмент нічого не надішле й поверне `code: "not_a_bot"`.
- `send_to_bot` надсилає повідомлення чи команду (наприклад `/start`) і до 20 с чекає відповіді; повертає текст і кнопки.
- Команди одному боту виконуються **по черзі**. Відповіддю вважається повідомлення бота, що прийшло після вашої команди (а якщо бот вказав, на яке повідомлення відповідає, — то саме на неї). Старі чи фонові повідомлення бота не сприймаються як відповідь. Повну гарантію дає лише бот, який ставить `reply_to`; Telegram цього не вимагає.
- `click_button` шукає кнопку за текстом — спершу точний збіг, потім без урахування регістру й пробілів по краях. Якщо кнопки немає, одразу повертає `ok: false`, `code: "button_not_found"` і список `available_buttons`.
- Для URL-кнопки посилання не відкривається, а повертається в полі `url`. Якщо бот показав спливне сповіщення, його текст — у полі `bot_answer`.

## Відмінності Windows і macOS — коротко

| | macOS | Windows |
|---|---|---|

| Активація середовища | `source .venv/bin/activate` | `.venv\Scripts\Activate.ps1` (PowerShell) |

| Копіювання `.env` | `cp` | `copy` |
| Конфіг Claude Desktop | `~/Library/Application Support/Claude/claude_desktop_config.json` | `%APPDATA%\Claude\claude_desktop_config.json` |

## Безпека й обмеження

- Секрети (`.env`, `data/`) не потрапляють у git, але зберігаються на диску у відкритому вигляді. Захистіть комп'ютер паролем і шифруванням диска.
- Дані, які повертають інструменти, бачить модель, з якою працює ваш MCP-хост (див. на початку). Не просіть Claude читати те, що не готові передати моделі.
- Це автоматизація **особистого акаунта**. Telegram обмежує частоту запитів: за надто частих запитів API відповідає `FloodWait`. Короткі паузи (до хвилини) сервер чекає сам, довші — одразу повертає `retry_after`, щоб не зависати; фонове вивантаження чекає до 15 хвилин, далі ставиться на паузу. Масові вступи в канали, великі вивантаження й розсилки можуть призвести до тимчасового, а за зловживання — і постійного блокування акаунта. Користуйтеся помірно й дотримуйтесь [Умов користування Telegram API](https://core.telegram.org/api/terms).
- Історія чужих чатів і списки учасників — це персональні дані інших людей. Збирайте й зберігайте їх лише в межах закону (зокрема GDPR) і правил самих чатів.
- Не використовуйте цей сервер для спаму, збору даних без підстав чи будь-яких дій, які порушують права інших.

## Усунення проблем

| Симптом | Що робити |
|---|---|
| «Сессия не найдена» | Виконайте крок 5 (`python -m app.auth`) із цієї самої папки. |
| «Сессия протухла или отозвана» | Завершили сеанс у Telegram — повторіть крок 5; перед цим видаліть `data/session.session`. |
| «TELEGRAM_API_ID / TELEGRAM_API_HASH не заданы» | Перевірте `.env` (крок 4): файл має лежати в корені проєкту й називатися саме `.env`. |
| Код не приходить | Дивіться в самому додатку Telegram (чат «Telegram»), а не в SMS. |
| `FloodWait` | Зачекайте вказаний час, зменшіть `limit`, не робіть багато запитів поспіль. |
| «Сессия Telegram занята другим процессом» (`session_busy`) | Сесією вже володіє інший процес: сервер у Claude Desktop **і** в Claude Code одночасно, або вивантаження чи вхід у терміналі при запущеному Claude. Залиште один: закрийте зайве (Claude — повністю) і повторіть. |
| Великий файл обривається | Claude обірвав виклик за таймаутом. Завантажуйте менше файлів за раз. Недокачаний файл не зберігається. |
| Вивантаження в статусі `interrupted` / `paused` | Продовжіть: `export_resume(job_id)` або `python -m app.export --resume <job_id>`. |
| `incomplete_download` | Розмір завантаженого файлу не збігся з Telegram — повторіть запит. |
| Чат не знаходиться за id | Перевірте id через `list_dialogs`; акаунт має бути учасником чату. Для публічних чатів можна передати `@username`. |
| `ModuleNotFoundError: app` | Сервер запущено не з кореня проєкту й без `PYTHONPATH`. Дотримуйтесь конфігу з docs/CLAUDE_DESKTOP.md. |

## Розробка

```
pip install -r requirements.txt -r requirements-dev.txt -c requirements.lock
python -m pytest -q tests
```

Тести не звертаються до Telegram: вони використовують підставні клієнти й тимчасову папку даних (`MTPROTO_DATA_DIR`). Серед них — справжній запуск сервера з MCP `initialize` і `tools/list` через stdio. Той самий набір запускає CI (`.github/workflows/ci.yml`) на Linux, macOS і Windows із чистою установкою з `requirements.txt`.
